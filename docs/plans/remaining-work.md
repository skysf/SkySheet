## 二、排查出来、还没修的问题

2026-11-15 的五组只读排查一共找出约 60 个问题。2026-11-16 作者说「电脑资源有限，只修紧急、重要的」：

- 下面这些以后单独排期。

每条都是读代码推出来的，还没复现，修之前要先复现。行号是 2026-11-15 的，可能已经变了。

### 认表格（describe_sheet 和 SQL 用的表格块）

- **横向求和、常量求和的数据行被当成合计行删掉**（`TableBlocks.swift`）。
  - main 的规则是：末行只要有以 `SUM(` 或 `SUBTOTAL(` 开头的公式，就当合计行。所以每行都用 `=SUM(B2:C2)` 求小计的表，会丢掉最后一条记录。
  - PR #12 试了五轮收窄这条规则，每一种写法都在别的表格上比 main 差，最后整个退回 main。比 main 差的情况有：
    - 认不出带冒号或空格的「合计」；
    - 把「合计划款」「Summer」当成合计；
    - 吞掉第一条记录；
    - 让合计重复计入，算成两倍。
  - 以后再做，先收集一套由真实表格组成的回归用例（两行表头、手填合计、横向合计行），再设计规则。底线是 main 能处理对的表，一张都不许变差。

### AI、MCP 和连接 Claude 的设置

- **配置文件读取失败被当成「不存在」**（`AIClientConfig.swift`）。配置文件没有读权限、但目录可写时，点 Connect 可能用最小配置覆盖掉用户的其他设置，而且不备份。应该只在确实不存在时新建。
- **配置文件被并发修改时丢更新**（同上）。SkySheet 读完配置以后，Claude 或编辑器又改了它，SkySheet 写回时会盖掉这次修改。应该在写回前再读一次比对。
- **sheet 名首尾的空格被去掉**（`AIWorkbooks.swift`）。两张表分别叫 `Data` 和 ` Data ` 时，可能读写到另一张。
- **长主目录回退到 /tmp 的套接字**（`MCPBridge.swift`、`MCPUnixSocket.swift`）。同一台 Mac 上的其他用户可以冒充服务端。小程序发正文之前，应该先核对对方进程的 UID。
- **App Translocation 的临时路径被写进 Claude 配置**（`AIClientStatus.swift` 等）。从下载文件夹或 dmg 直接运行时，配置里记下的小程序路径过后会失效。到「给别人用」（M10）时一定要修。
- **小程序的 stdin 没有长度上限**（`SkySheetMCP/main.swift`）：超长输入能把小程序的内存吃光。
- **两份 app 同时运行时，连接会串到另一份**（`AppConnection.swift`）。
- **Claude Code 断开失败，仍显示成功**（`ClaudeCodeSetup.swift`）。
- **同一张表里两个表头只差 Unicode 写法时，给 AI 看的列名一模一样**（`TableBlocks.swift`）。
- **自动认出的表格块按外框一格一格走**（`describe_sheet` 和 `query` 用的表格块）。AI 分两次写（先 A1:A10000，再 XFD1），就能拼出上亿格的外框，把内存吃光。要修，得先定太大的块怎么处理。PR #15 发现，没修。
- **界面上的合并不限面积**。PR #15 只给 AI 的合并加了 5 万格的上限；界面上手动合并超大区域，照旧会一格一格展开。
- **AI 删表、改名时，workbook 级的定义名称照旧跟着改**。PR #15 只拦了原始 sheet 格子里的公式，定义名称还会被改写。
- **别的 AI 拒绝在撤销组里抛错，会清掉用户的重做历史**。
  - PR #15 把它自己新加的拒绝挪到了开组之前；main 原有的拒绝还在组里抛，同样会把用户撤掉的那一步挤出重做栈。这些拒绝包括：
    - add_sheet、edit_sheet 名字不合规矩，或者要删最后一张表；
    - format_cells 合并会丢内容，或者切过已有的合并块；
    - edit_rows_columns 插删时挤出表外、碰到读不懂的公式、切开数组公式。
  - 没改到任何东西的 AI 调用（比如写进一样的值）也会留下一个空组。
  - 以上是读代码推断的，还没实测。

### 读文件

- **zip 声明的大小会被用来预先分配内存**（`Deflate.swift`、`ZipArchive.swift`、`SaveVerifier.swift`）。伪造的文件能一次吃掉近 4 GiB。应该边解边长，并给单个部件和总量设上限。
- **`t="d"` 日期格子里的毫秒被截掉**（`WorksheetPart.swift`）。
- **csv 里非法的秒数被当成合法日期**，极端值还会崩溃（`CSVReader.swift`）。
- **几种特制的数字字段会让程序崩溃**（`WorksheetPart.swift`、`XLSXReader.swift`）：
  - pane 的 xSplit=1e100；
  - 空的 `t="d"`；
  - 极大的行号、极大的 sheetId；
  - `min > max` 的列定义。
- **超过 16,384 列的 csv 在建窗口时崩溃**（`CSVReader.swift`、`SheetGeometry.swift`）。
- **只有图表页、没有工作表的工作簿会崩溃**（`XLSXReader.swift`、`SheetSession.swift`）。
- **`_xHHHH_` 转义里的 UTF-16 代理对没有组合起来**（`XMLFragments.swift`）。会读错字，保存后还会改坏字。
- **扩展名是 .tsv 的文件可能被猜成逗号分隔**（`WorkbookDocument.swift`、`CSVReader.swift`）。
- **Excel 的 `sep=` 首行被当成数据**（`CSVReader.swift`）。
- **zip 里有重复的条目名时，能打开但存不了**（`ZipArchive.swift`、`ZipWriter.swift`）。
- **关系里写了的部件在 zip 里找不到时，被当成「本来就没有」**（`XLSXReader.swift`）。共享字符串格可能读成空的，保存时文字会丢。应该报 missingPart。
- **sheetData 里面的 `mc:AlternateContent` 重写时只写选中的那一支**（很少见）。保存时只写那一支里读到的格子，外壳不保留，main 也不保留。不认识的 Choice 里多出来的内容不读，main 是两支都读、后读的盖掉先读的。PR #17 留下的。

### 保存和恢复

- **改名的 sheet 还被图表、透视缓存、条件格式、数据验证引用着**（`XLSXWriter.swift`、`WorkbookEditing.swift`）。改名后再新建一张同名的表，图表会读到新表。应该像插删行列一样，拒绝这种改名。
- **StructureLock 只认字面写法的属性**（`StructureLock.swift`）。`sheet='Data'`、`sheet = "Data"` 这种写法能绕过插删行列的保护。
- **未修改格子里的 inline 富文本和注音，保存时丢失**（`WorksheetWriter.swift`、`WorksheetPart.swift`）。
- **新建或改名的 sheet 可以和保留的图表页重名**（`WorkbookWriter.swift`），会写出不合法的工作簿。
- **稀疏的表另存 csv 时，把整个矩形展开**（`CSVWriter.swift`）。
- **UTF-16 编码的 workbook.xml 能打开、存不了**（`XMLFragments.swift`）。
- **文件名很长时备份目录名超长，导致不能覆盖保存**（`BackupStore.swift`）。
- **只有 xlsx、没有 JSON 的孤儿恢复副本永远不会被发现**（`RecoveryStore.swift`）。

PR #17（2026-11-16、17）修读文件、保存、恢复时留下的。都是看得见的限制，不会悄悄存错：
- **切不了词、又有相对引用的共享公式**，比如主公式里有结构化引用 `Table1[Amount]`：
  - 跟随者的公式算不出来：界面显示「=」，AI 读到空公式，格子显示文件里的缓存值。
  - 这种组整组锁住，主格和跟随者都只能在 Excel 里改。
  - 要真正支持，得让公式引擎认结构化引用。
- **从这种组往外复制粘贴**：粘过去的格子没有公式可写，只有值，会显示 `#NAME?`。⌘Z 能撤回。
- **粘贴、往下填充切不了词的公式时，相对引用不跟着平移**。main 原有。
- **模拟运算表的区域不能在 SkySheet 里改**（Excel 也不许只改一部分）。有模拟运算表的表整张锁住插删行列：它的输入格可能在表上任何位置，没去改写 `r1`、`r2`、`ref`。
- **能平移的共享公式组改了几格以后，整组逐格展开写**，和 main 一样，不保留共享结构。
  - 插删行列以后，这张表的 `<f>` 记录整个清空，公式照常写。
  - 整轮撤销换回能算准的组、或带 `ca` 这类属性的公式时，记录不随快照回来，保存时照常写原文。
  - 这些情况公式都不丢，只是不再保持共享和那些属性。
- **写回时 `XMLFragments` 按本地名找顶层元素，不看命名空间**。现实中的文件没有撞名的，插删保护本来也从严。
- **改写 `<definedNames>` 时，带前缀的属性按去掉前缀的名字写回**。main 原有。
- **理论上的漏洞**：打开以后从没重算过、又没有缓存值的空原文格，被一模一样的空原文改写时看不出来。App 打开文件都会整本重算，实际碰不到。
- **没验证过的**：
  - Excel、Numbers、腾讯文档打开我们存的文件，见第一节；
  - MS-OI29500 对 `f` 元素的说明没查到。共享区域里夹着自己写了公式的格子，依据的是 ECMA-376 第 1 部分 18.3.1.40。
